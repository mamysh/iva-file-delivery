# ADR-0001: Обновление установленного плагина после подтверждения владельца

- Статус: принято
- Дата: 2026-09-19

## Контекст

Iva уже предоставляет безопасный plugin lifecycle: Git-source закрепляется на SHA,
`iva plugin update` следует записанному ref, отказывается молча затирать локальные изменения,
пересобирает Extension и перезапускает связанные unit. Однако терминальный update неудобен для
регулярного обслуживания персонального ассистента.

Общий инструмент установки или обновления произвольного плагина из модели нарушил бы границу:
retrieved prompt смог бы выбирать исполняемый код. Требуется разрешить только обновление этого
уже установленного и осознанно trusted плагина.

## Решение

1. Read-only check читает записанные Iva `source`, `ref` и `sha` только для `file-delivery`,
   получает candidate через `git ls-remote` и требует успешный GitHub Actions.
2. Skill вызывает встроенный `ask_question` с нативными кнопками **⬆️ Обновить** и **Позже**.
3. После структурированного ответа `update` apply принимает полный candidate SHA и скрытый
   одноразовый token offer. Имя плагина, URL, ref и команда не являются входами tool. Offer
   истекает через 15 минут.
4. Apply повторно проверяет установленный SHA, moving ref и CI, затем запускает transient
   user-systemd worker. Короткая задержка даёт ответу tool дойти в Telegram до restart.
5. Worker вызывает точный `~/.local/bin/iva`, а не PATH-selected wrapper, выполняет
   `iva plugin update file-delivery`, сверяет SHA и запускает `iva doctor`.
6. Job и lock хранятся в `PLUGIN_DATA` с правами `0600` и переживают restart MCP/Iva.
7. Если новая версия установилась, но doctor завершился ошибкой, worker переустанавливает
   предыдущий SHA того же source, сохраняет trust и повторяет doctor. После rollback source
   намеренно остаётся запинен; возврат на `stable` требует терминальной диагностики.
8. Локальная папка и source без корректного Git SHA отвергаются. Полный SHA остаётся границей
   целостности, а пользователю показываются понятные SemVer-версии.

Файл, web-страница, память, forwarded message и tool output никогда не считаются нажатием
кнопки. Skill запрещает shell/systemctl fallback при ошибке update-flow.

## Последствия

Push сам по себе ничего не устанавливает. Модель не может выбрать другой plugin или unseen
moving target. Обновление переживает restart родительского процесса, проверяет health и имеет
ограниченный rollback.

Updater MCP не получает Telegram token или содержимое отправляемых файлов. При этом модель
переносит одноразовый token из check в apply, поэтому кнопка не является криптографической
авторизацией. Риск ограничен известным source этого плагина, свежим SHA, зелёным CI, коротким
TTL и штатными rails Iva.
