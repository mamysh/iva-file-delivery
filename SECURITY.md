# Security Policy

## Поддерживаемые версии

Исправления безопасности выпускаются для текущей стабильной версии и состояния ветки `main`.
До публичного объявления следующей линии поддерживается `0.3.x`.

## Как сообщить об уязвимости

Используйте **Security → Report a vulnerability** в GitHub-репозитории. Private Vulnerability
Reporting позволяет обсудить проблему без публичного issue.

Укажите версию или commit, минимальный сценарий воспроизведения, ожидаемое влияние и
синтетический пример. Не присылайте действующий Telegram bot token, реальные chat/user ID,
содержимое файлов, абсолютные пути сервера, полные tool traces или несокращённые логи.

Обычные ошибки без влияния на безопасность можно публиковать в GitHub Issues после очистки
данных.

## Модель угроз

Плагин выполняется как Eve Extension внутри процесса агента и видит окружение Iva, включая
`TELEGRAM_BOT_TOKEN`. Поэтому устанавливать следует только просмотренный код из известного
commit или release tag.

Updater работает отдельным доверенным stdio MCP-процессом. Iva передаёт ему `PLUGIN_ROOT` и
`PLUGIN_DATA`, но не Telegram token. Trust нужен для запуска updater, а не для file tool.

Защита назначения не опирается на инструкции модели:

1. tool не принимает `chat_id`;
2. текущий turn обязан принадлежать аутентифицированному Telegram-пользователю;
3. `chat_type` обязан быть `private`;
4. `chat_id` обязан совпадать с `user_id` того же auth context.

Защита источника ограничивает чтение каталогом `vault/attachments/`. Инструменты принимают только
относительные пути, разрешают физически находящиеся внутри каталога обычные файлы, повторно
проверяют открытые file descriptor, отклоняют скрытые компоненты, пустые файлы и размер выше
50 МБ на файл. Альбом содержит 2–10 документов разных форматов; каждый проверяется до
отправки всей группы. `O_NOFOLLOW` и `realpath` закрывают обычный выход через симлинк; это не превращает
общий Unix-аккаунт в полноценную multi-tenant sandbox.

Инструменты передают байты напрямую Telegram Bot API через TLS и не создают публичную ссылку. Они не
добавляют caption, а значит произвольный текст модели идёт через обычный Outbox Iva. Плагин не
логирует токен или содержимое файлов и возвращает только итог, безопасные имена, MIME-типы,
размеры и Telegram message ID. Альбом Telegram отображает как группу, но API возвращает
отдельный message ID для каждого файла.

## Обновление из чата

Updater не принимает имя плагина, URL репозитория, ref или shell-команду. Он читает записанный
Iva source только для `file-delivery`, создаёт offer на конкретный SHA и разрешает apply лишь
в течение 15 минут после успешного GitHub Actions. Текущая и кандидатная версии читаются из
manifest на установленных SHA и проходят строгую SemVer-проверку; offer появляется только для
более высокой версии.

Skill использует встроенный `ask_question` с двумя кнопками. Apply дополнительно требует
одноразовый token этого offer и повторно проверяет moving ref и CI. Текст файла, web-страницы,
памяти или пересланного сообщения не считается подтверждением.

Обновление выполняет точный `~/.local/bin/iva` в отдельном transient user-systemd unit. Worker
вызывает штатный `iva plugin update file-delivery`, проверяет установленный SHA и запускает
`iva doctor`. Если новая версия уже установилась, но диагностика не прошла, worker пытается
вернуть предыдущий SHA того же source и проверить его. Job и lock имеют права `0600` и не
содержат Telegram token или содержимое файлов.

Модель всё ещё переносит одноразовый token из check в apply, поэтому кнопка не является
криптографической авторизацией. Остаточный эффект ограничен уже доверенным Git-source этого
плагина, свежим SHA, зелёным CI, коротким TTL и штатными plugin rails Iva.

## Осознанные ограничения

- Содержимое файла не проходит DLP или secret scan. Граница назначения защищает от отправки
  другому Telegram-получателю, но не определяет, допустимо ли владельцу получить эти данные.
- Байты upload идут напрямую через tool и не проходят текстовый outbound scanner Iva.
- Относительный путь, имя, размер, MIME-тип и tool result могут сохраниться в trace Ивы.
- Telegram является внешним обработчиком данных и применяет собственные правила хранения.
- Пользователь или другой процесс с тем же Unix-аккаунтом и правом записи в attachments может
  менять файлы. Плагин рассчитан на персональную, а не враждебную multi-user установку.
- Ограничение 50 МБ соответствует текущему публичному `sendDocument`; Telegram может изменить
  его в будущем.

Если bot token попал в commit, issue, PR, лог, artifact или чат, немедленно отзовите его через
BotFather и настройте новый. Удаление строки последующим commit не отменяет компрометацию и не
очищает историю Git.
