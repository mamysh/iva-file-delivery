# Security Policy

## Поддерживаемые версии

Исправления безопасности выпускаются для текущей стабильной версии и состояния ветки `main`.
До публичного объявления следующей линии поддерживается `0.1.x`.

## Как сообщить об уязвимости

Используйте **Security → Report a vulnerability** в GitHub-репозитории. Private Vulnerability
Reporting позволяет обсудить проблему без публичного issue.

Укажите версию или commit, минимальный сценарий воспроизведения, ожидаемое влияние и
синтетический пример. Не присылайте действующий Telegram bot token, реальные chat/user ID,
содержимое файлов, абсолютные пути сервера, полные tool traces или несокращённые логи.

Обычные ошибки без влияния на безопасность можно публиковать в GitHub Issues после очистки
данных.

## Модель угроз

Плагин выполняется как Eve Extension внутри процесса агента и видит окружение Iva, включая
`TELEGRAM_BOT_TOKEN`. Поэтому устанавливать следует только просмотренный код из известного
commit или release tag.

Защита назначения не опирается на инструкции модели:

1. tool не принимает `chat_id`;
2. текущий turn обязан принадлежать аутентифицированному Telegram-пользователю;
3. `chat_type` обязан быть `private`;
4. `chat_id` обязан совпадать с `user_id` того же auth context.

Защита источника ограничивает чтение каталогом `vault/attachments/`. Tool принимает только
относительный путь, разрешает физически находящийся внутри каталога обычный файл, повторно
проверяет открытый file descriptor, отклоняет скрытые компоненты, пустые файлы и размер выше
50 МБ. `O_NOFOLLOW` и `realpath` закрывают обычный выход через симлинк; это не превращает
общий Unix-аккаунт в полноценную multi-tenant sandbox.

Tool передаёт байты напрямую Telegram Bot API через TLS и не создаёт публичную ссылку. Он не
добавляет caption, а значит произвольный текст модели идёт через обычный Outbox Iva. Плагин не
логирует токен или содержимое файла и возвращает только итог, безопасное имя, MIME-тип, размер
и Telegram message ID.

## Осознанные ограничения

- Содержимое файла не проходит DLP или secret scan. Граница назначения защищает от отправки
  другому Telegram-получателю, но не определяет, допустимо ли владельцу получить эти данные.
- Байты upload идут напрямую через tool и не проходят текстовый outbound scanner Iva.
- Относительный путь, имя, размер, MIME-тип и tool result могут сохраниться в trace Ивы.
- Telegram является внешним обработчиком данных и применяет собственные правила хранения.
- Пользователь или другой процесс с тем же Unix-аккаунтом и правом записи в attachments может
  менять файлы. Плагин рассчитан на персональную, а не враждебную multi-user установку.
- Ограничение 50 МБ соответствует текущему публичному `sendDocument`; Telegram может изменить
  его в будущем.

Если bot token попал в commit, issue, PR, лог, artifact или чат, немедленно отзовите его через
BotFather и настройте новый. Удаление строки последующим commit не отменяет компрометацию и не
очищает историю Git.
